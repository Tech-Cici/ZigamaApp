# Deploying Zigama

Three pieces go out:

| Piece | Where | Cost |
|---|---|---|
| **API** (`backend/`) | Render web service | free |
| **Staff console** (`web/`) | Render static site | free |
| **Customer app** (`mobile/`) | APK via EAS | free |
| Database | Neon Postgres | free |

The only thing that ever costs money is a Google Play listing ($25 one-off),
which you do **not** need to hand someone an APK, and an Apple Developer
membership ($99/year) if you want an iOS build.

Steps 1–2 need accounts, so they are yours to do. Everything in the repo is
already prepared for them.

---

## Why this is worth doing

Right now the APK has your laptop's IP baked into it. That means every phone
must be on your network, your Mac must be awake and running two servers, and
changing Wi-Fi breaks the build. Deploying removes all of it — and gives you a
staff console anyone can open with a link.

It also moves you off a development database that tolerates **two** connections.

---

## 1. Database (Neon)

1. Sign up at **neon.tech** — no card required.
2. Create a project called `zigama`. Any region.
3. Copy the connection string:

   ```
   postgresql://USER:PASSWORD@ep-xxx.region.aws.neon.tech/neondb?sslmode=require
   ```

Keep it for step 2. **Never commit it.**

No code changes are needed — the app talks to any standard Postgres. The local
WASM server was only ever a development convenience.

---

## 2. Push, then deploy both services

The repo already contains `render.yaml`, which describes both services, so
Render can set them up together.

```bash
cd "/Users/ciara/Documents/Zigama App/banking-platform"
git push
```

In Render: **New → Blueprint → select your repo**. It reads `render.yaml` and
offers two services: `zigama-api` and `zigama-staff`.

Render will prompt for the values marked as secrets:

| Service | Variable | Value |
|---|---|---|
| zigama-api | `DATABASE_URL` | your Neon string from step 1 |
| zigama-api | `CORS_ORIGINS` | leave blank for now — you need the console URL first |
| zigama-staff | `VITE_API_URL` | leave blank for now — you need the API URL first |

`JWT_SECRET` and `PAYMENT_WEBHOOK_SECRET` are generated by Render
automatically; you never see or set them.

### Then wire the two together

Render assigns URLs like `https://zigama-api.onrender.com` and
`https://zigama-staff.onrender.com`. Once both exist:

1. **zigama-staff** → Environment → set `VITE_API_URL` to
   `https://zigama-api.onrender.com/api` → **Manual Deploy**.
   Vite inlines this at build time, so it needs a rebuild, not just a restart.
2. **zigama-api** → Environment → set `CORS_ORIGINS` to
   `https://zigama-staff.onrender.com` → save.

That second one matters: without it the API reflects any origin, which lets a
page on another site call it with a signed-in operator's credentials.

### Check it

```
https://zigama-api.onrender.com/api/health
```

You want `{"status":"ok","database":"reachable",...}`. `degraded` means
`DATABASE_URL` is wrong.

## 3. Seed the production database

Run from **your laptop**, pointed at Neon — the seed is a dev dependency and is
not installed on the server:

```bash
cd backend
DIRECT_DATABASE_URL="<your-neon-connection-string>" npm run db:seed
```

Creates the staff logins, four customers, and two applications awaiting
approval. **Run once**, before anyone uses it — it wipes and rebuilds.

Now open the staff console URL and sign in with `admin@zigama.test` /
`Admin@12345`.

---

## 4. Build the APK against the deployed API

Edit the `preview` profile in `mobile/eas.json` — replace `REPLACE-ME`:

```json
"EXPO_PUBLIC_API_URL": "https://zigama-api.onrender.com/api"
```

Note the `/api` suffix. Then:

```bash
cd mobile
npx eas-cli@latest build --platform android --profile preview
```

This APK works **anywhere** — any network, mobile data, no laptop. Send the
download link to anyone.

You can now delete the `lan` profile and the `usesCleartextTraffic` setting in
`app.json`: both exist only to talk to a laptop over plain HTTP, and Render
serves HTTPS.

---

## The cold start

Render's free tier idles a service out after ~15 minutes; the next request takes
30–60 seconds while it boots.

The app already handles this — it pings `/api/health` on launch so the server
wakes while the user is reaching for their PIN, allows 75 seconds for the first
request, and says the server is waking rather than something generic.

For a live demo, open the health URL a minute beforehand. Always-on is about
$7/month if you need it.

Neon also autosuspends but wakes in about a second.

---

## What is deliberately not here

- **Play Store / App Store submission.** Needs the paid accounts above. The
  `production` profile in `eas.json` builds an AAB when you want one.
- **A custom domain.** The `onrender.com` URLs are HTTPS already.
- **Real MTN credentials.** `PAYMENT_PROVIDER=mock` is set; switching to `mtn`
  needs an API user and subscription key registered on MTN's portal.
